# Supabase スリープ防止ワークフロー 設計

作成日: 2026-07-02

## 背景・目的

Supabase 無料プランは 7 日間 DB へのアクセスがないとプロジェクトが自動的に一時停止（スリープ）する。
本アプリのバックエンドは `DATABASE_URL`（PostgreSQL 接続文字列）を使い SQLAlchemy で直接接続している。
GitHub Actions のスケジュール実行で定期的に軽量クエリを投げ、スリープを防ぐ。

## 方針

- **接続方法**: `psql` で `DATABASE_URL` に直接接続し `SELECT 1;` を実行する。
  既存の接続方式（PostgreSQL 直接接続）をそのまま使え、確実に DB を起こせる。
- **実行頻度**: 3 日に 1 回。

### 実行頻度を 3 日にする理由

GitHub Actions の `schedule` は固定のカレンダー日にトリガーされ、ジョブが失敗しても
次回が前倒し・リスケジュールされることはない。次回は次の予定日にそのまま実行される。

- 5 日間隔だと、1 回失敗した場合に「最後の成功 → 次の成功」が最大約 10 日になり 7 日期限を超える。
- 3 日間隔なら、1 回失敗しても最後の成功から次の成功まで最大約 6 日に収まり、7 日期限内。

## ファイル構成

- 新規: `.github/workflows/keep-db-alive.yml`（既存の `ci.yml` とは独立したワークフロー）

## ワークフロー内容

- **トリガー**
  - `schedule: cron: '0 3 */3 * *'`（毎月 1,4,7,...,28,31 日の UTC 3:00 = JST 12:00）
  - `workflow_dispatch`（手動実行を可能にし、動作確認できるようにする）
- **ジョブ**: `ubuntu-latest`。ランナーに `psql` が標準搭載されているため追加インストール不要。
- **ステップ**: `psql "$DATABASE_URL" -c 'SELECT 1;'` を実行。
- **シークレット**: `DATABASE_URL` を GitHub リポジトリの Secrets に登録し、`env` 経由で参照する（値はログに出さない）。

## エラーハンドリング

- クエリ失敗時はジョブが失敗ステータスになり、GitHub からメール通知が届くため DB 接続異常に気づける。

## ユーザー側の作業（コードでは対応不可）

- リポジトリの Settings → Secrets and variables → Actions で `DATABASE_URL` を登録する。
  - Supabase の接続文字列を使用し、`sslmode=require` を付与することを推奨。

## 動作確認方法

1. ワークフローを push 後、Actions タブから `workflow_dispatch` で手動実行し、緑✓になることを確認する。
2. ログに `SELECT 1` の結果（`?column?` / `1`）が出ることを確認する。
3. Supabase ダッシュボードで最終アクセス時刻が更新されることを確認する。
