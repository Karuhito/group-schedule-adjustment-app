## 修正: ログアウト時のCookie削除属性を発行時と統一

**種別**: 修正
**対象ファイル**: `backend/app/routers/auth.py`

### 変更内容
- `logout` エンドポイントの `delete_cookie` に `httponly` / `samesite` / `secure` 属性を追加
- `set_cookie` と同じ `is_secure` フラグ（`app_env == "production"` で判定）を使い属性を揃えた

### 理由
本番環境（Vercel + Fly.io クロスサイト構成）では Cookie を `samesite=none; secure=True` で発行しているが、`delete_cookie` に属性が未指定だとブラウザが別物として扱い、ログアウトしても Cookie が削除されない問題があった（issue #18）

## 修正: Discord OAuth に state パラメータを追加して CSRF 対策 (issue #16)

**種別**: 修正
**対象ファイル**: `backend/app/routers/auth.py`, `backend/tests/test_auth.py`

### 変更内容
- `secrets.token_urlsafe(32)` で state を生成し `/auth/discord` の OAuth URL に付与
- state を httponly Cookie（`oauth_state`、有効期限10分）にセット
- `/auth/discord/callback` で Cookie の state とクエリの state を `secrets.compare_digest` で比較し、不一致・欠落なら `/login?auth_error=invalid_state` へリダイレクト
- コールバック成功後は `oauth_state` Cookie を削除
- テストを補強（state 検証、欠落・不一致ケースの拒否確認）

### 理由
OAuth CSRF 攻撃（攻撃者が用意した認可コードを被害者のセッションに紐付けるログイン CSRF）への対策（issue #16）
